# Архитектура и контракты

## Сценарий

1. main.py запрашивает GET /questions у Questions на порту 8101.
2. main.py читает demo_answers.json и отправляет POST /check в Checker на порту 8102.
3. main.py отправляет результат проверки через POST /reports в Reports на порту 8103.
4. main.py выводит счёт, процент и идентификатор сохранённого отчёта.

Общий main является HTTP-клиентом и координатором. Он не запускает чужую бизнес-логику через import.
run_all.py является отдельным средством запуска процессов. После завершения main он останавливает только созданные им процессы.
Падение одного сервиса не завершает остальные при ручном запуске в терминалах.

## GET /health: каждый сервис

HTTP 200, например {"service": "questions", "status": "ok"}.
Это проверка работающего процесса и HTTP, а не готовности учебных методов или данных.

## GET /questions: сервис Questions

HTTP 200:

    {"questions": [
      {"id": "q1", "text": "Какой тип хранит пары ключ-значение?",
       "options": {"A": "list", "B": "dict"}}
    ]}

Реальный учебный файл содержит два вопроса. Порядок вопросов сохраняется.
GET /questions возвращает все вопросы и не включает правильные ответы.

## POST /check: сервис Checker

Тело запроса:

    {"answers": {"q1": "B", "q2": "A"}}

HTTP 200:

    {"correct": 2, "total": 2, "percent": 100.0}

Пропущенный ответ считается неправильным. total равен числу вопросов в ключе ответов.
Неизвестный id вопроса, неизвестная буква варианта или неподходящий тип дают HTTP 400.
Пустой словарь answers при двух вопросах даёт 0, 2, 0.0.
При пустом ключе и пустом answers результат 0, 0, 0.0.

## POST /reports: сервис Reports

Тело запроса:

    {"result": {"correct": 2, "total": 2, "percent": 100.0}}

HTTP 201:

    {"report": {
      "id": "<непустой уникальный идентификатор>",
      "result": {"correct": 2, "total": 2, "percent": 100.0}
    }}

GET /reports возвращает HTTP 200 с {"reports": [...]}.
После перезапуска сервиса ранее сохранённые отчёты должны оставаться.

## Ошибки

Ошибки приходят как {"error": "объяснение"}.
400: неправильный запрос. 404: неизвестный маршрут. 405: неподдержанный HTTP-метод.
501: учебный метод пока не реализован. 500: повреждённый файл данных или другая внутренняя ошибка.
Недоступность процесса и тайм-аут превращаются в ClientError в общем клиенте.
В main ошибка приводит к понятному сообщению и коду завершения 1.
