# Задания по шагам

## 1. Вопросы: модули, классы и JSON

Файл services/questions/domain.py.

- Question.__init__: сохрани id, text и отдельную копию options.
- Question.as_dict: верни новый словарь с id, text и отдельной копией options.
- QuestionService.list_questions: прочитай свой JSON через with и UTF-8.
  Создай объекты Question, затем верни список их словарей в исходном порядке.
- Считай, что содержимое существующего корректного JSON соответствует samples.
  Отсутствующий файл и повреждённый JSON не скрывай.
- Пустой JSON-массив даёт [].

Проверь: python -m services.questions.app, затем открой http://127.0.0.1:8101/questions.

## 2. Проверка: условия и исключения

Файл services/checker/domain.py.

- AnswerChecker.__init__: сохрани путь к ключу ответов.
- check(answers) каждый раз читает JSON-ключ.
- answers должен быть словарём, id и буквы должны быть строками.
- Известные id и разрешённые буквы бери из ключа. Регистр букв важен.
- Неизвестные id и варианты вызывают ValueError. Не меняй answers.
- correct — количество совпадений, total — размер ключа.
- percent = round(correct / total * 100, 1), при total=0 верни 0.0.
- Не возвращай сам ключ правильных ответов через API.

## 3. Результаты: файлы и состояние

Файл services/reports/domain.py.

- list_reports читает список отчётов. Только отсутствие файла означает [].
  Ошибка JSON должна оставаться видимой.
- save(result) принимает словарь с correct, total и percent.
- correct и total — целые числа, bool не принимается. 0 <= correct <= total.
- percent — int или float, bool не принимается. Он должен совпадать с формулой выше.
- Неверные данные вызывают ValueError ДО создания/изменения файла.
- Создай новый id через uuid.uuid4().hex.
- Отчёт содержит только id и копию result с тремя указанными ключами.
- Загрузи прежний список, добавь отчёт и запиши весь список в JSON.
- Создай родительскую папку, если её нет. UTF-8, ensure_ascii=False, indent=2.
- Верни сохранённый отчёт. Сохраняй историю между экземплярами ReportStore.
- В этом учебном сервисе HTTP-запросы обрабатываются последовательно,
  поэтому параллельную запись одного файла здесь не реализуем.

## 4. Автоматические тесты

Готовые tests/test_contracts.py показывают unittest, временные файлы и HTTP-запросы.
В tests/test_student.py замени три skip-заготовки настоящими проверками:

1. Question.as_dict не выдаёт ссылку на внутренний options.
2. После save создание нового ReportStore с тем же путём видит старый отчёт.
3. Неверный result не изменяет уже существующий файл.

Тестовый метод с pass ничего не проверяет. Используй assertEqual, assertIsNot или assertRaises.

## 6. Самостоятельное расширение

После обязательной части добавь четвёртый сервис Statistics.
GET /stats должен возвращать число отчётов и средний percent (0.0 для пустого списка).
Statistics получает данные через GET /reports и не читает чужой файл.
Включи его URL и порт в config.py, вызови из main и добавь запуск в run_all.py.
Напиши тест обычного и пустого результата. Это дополнительное задание.
