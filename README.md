# Домашняя работа №4: три микросервиса и общий main

Собери «Мини-квиз»: сервис вопросов, сервис проверки ответов и сервис результатов.
Каждый сервис работает в отдельном процессе и слушает собственный HTTP-порт.
Общий main.py обращается к ним по HTTP и собирает сценарий викторины.
Это учебные локальные HTTP-сервисы на стандартной библиотеке Python, без установки пакетов.

## Что уже готово

- HTTP-сервер, маршруты, JSON-запросы и сообщения об ошибках.
- HTTP-клиент с тайм-аутом и объяснением недоступности сервиса.
- Общий main.py, который вызывает сервисы по порядку.
- run_all.py для запуска трёх процессов и завершения их после демонстрации.
- Настройки портов, данные, тесты и демонстрационные ответы.

## Что делает ученик

1. Прочитай docs/architecture.md и docs/tasks.md.
2. Реализуй Question и QuestionService в services/questions/domain.py.
3. Реализуй AnswerChecker в services/checker/domain.py.
4. Реализуй ReportStore в services/reports/domain.py.
5. Добавь три собственных теста в tests/test_student.py.
6. Запусти общий сценарий и проверь, что недоступный сервис даёт понятную ошибку.
7. Запиши ответы на вопросы в answers.md.
8. Сделай commit и push.

## Быстрый запуск

Нужен Python 3.10 или новее. Команды выполняются из корневой папки проекта.

    python -m venv .venv
    python -m pip install -r requirements.txt
    python -m unittest discover -s tests -v
    python run_all.py

Выбери интерпретатор созданного окружения в редакторе или используй его полный путь.
На Windows это .venv\Scripts\python, на macOS/Linux это .venv/bin/python.
Сторонних зависимостей нет. Если команда python отсутствует, на Windows попробуй py.

До выполнения заданий /health работает, а учебные методы отвечают HTTP 501.
Часть тестов ожидаемо падает. Это показывает, какие методы ещё нужно реализовать.
Система не должна сообщать об успешном прохождении, если функция осталась заглушкой.

## Отдельный запуск: четыре терминала

    python -m services.questions.app
    python -m services.checker.app
    python -m services.reports.app
    python main.py --answers demo_answers.json

Каждую команду запускай в отдельном терминале из корня.
Остановка сервиса: Ctrl+C в его терминале.

## Настройки

По умолчанию используются 127.0.0.1 и порты 8101, 8102, 8103.
Переменные QUESTIONS_PORT, CHECKER_PORT, REPORTS_PORT меняют порты.
Общий main и сервисы читают одинаковые настройки из config.py.
REPORTS_FILE задаёт путь к файлу результатов, по умолчанию work_results/reports.json.

Для готового решения demo_answers.json даёт 2 правильных ответа из 2 и 100.0%.
Идентификатор сохранённого отчёта меняется при каждом запуске.

## Договорённости

- main.py не импортирует domain.py и не читает файлы сервисов.
- Сервис вопросов владеет своим questions.json.
- Сервис проверки владеет answer_key.json. Ответы не входят в публичные вопросы.
- Только сервис результатов пишет reports.json.
- Для повторного использования готовых модулей их можно импортировать.
  Общение между работающими сервисами происходит по HTTP.
- Тесты создают временные файлы. .venv и work_results не попадают в Git.

HTTP-обвязка предназначена для локального урока. Серверы привязаны к 127.0.0.1.
Распределённую авторизацию, Docker и базу данных в этом задании не требуем.
